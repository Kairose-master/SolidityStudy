# SOL-003 채점 기록

## 결과

통과

## 제출 내용 요약

- `totalDamage` 상태 변수 선언
- `internal pure` 보조 함수 `_multiply` 구현
- `previewAttack`에서 일반 피해와 치명타 피해 반환
- `recordDamage`에서 누적 피해를 상태에 저장하고 갱신값 반환

## 피드백 반영 과정

첫 수정에서는 `returns (uint256 totalDamage)`로 반환 변수와 상태 변수의 이름이 같아 섀도잉이 발생했다. 반환 변수의 이름을 제거해 상태 변수에 접근하도록 수정했다.

최종 제출의 `return totalDamage = totalDamage + damage;`는 논리적으로 유효하다. 저장본은 감사 시 상태 변경을 쉽게 확인하도록 대입과 반환을 두 줄로 정규화했다.

채팅의 Markdown 코드 블록과 `\_`, `\*` 같은 이스케이프 문자는 복사 과정의 흔적으로 보고 채점에서 제외했다.

## 보안 답변

`recordDamage`가 접근 제어 없는 `public` 함수이면 누구나 임의의 피해량을 반복 제출하여 `totalDamage`를 부풀릴 수 있다. 온체인 게임의 권위 있는 기록으로 사용하려면 허용된 게임 컨트랙트만 호출하게 하거나, 컨트랙트가 검증 가능한 전투 규칙으로 피해량을 직접 계산해야 한다.

- 상태 변수와 지역 변수 또는 반환 변수 사이에 섀도잉이 있는가?
