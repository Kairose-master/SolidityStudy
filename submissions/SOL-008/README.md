## 충족한 요구사항

- 중복 등록 방지와 등록 상태 관리
- calldata 배열의 입력 개수 및 원소 범위 검사
- 지역 storage 참조를 통한 호출자별 상태 배열 변경
- 최대 누적 점수 개수 10개 제한
- Checks와 Effects를 분리한 제한된 반복문
- `pop()`으로 마지막 점수 제거
- calldata 입력을 memory 배열로 가공해 반환
- preview 함수가 영구 상태를 변경하지 않음

## 피드백 반영 과정

첫 제출은 `register`, `addScores`, `removeLastScore`와 데이터 위치 사용을 정확히 구현했다. `previewDoubled`에서 각 입력이 1 이상 50 이하인지 검사하는 부분이 누락되어 0이나 50보다 큰 값도 처리할 수 있었다.

두 번째 제출에서 값 검사를 추가했지만 `require` 뒤의 세미콜론이 빠져 컴파일할 수 없었다. 최종 제출에서 세미콜론을 추가해 문법과 동작 요구사항을 모두 충족했다.

채팅에 섞인 Markdown 코드 울타리와 특수 공백은 복사 흔적으로 보고 저장본에서 제거했다.

## 보안 답변

입력 배열 길이 상한을 제거하면 반복 횟수와 가스 소비가 입력 크기에 따라 계속 증가한다. 블록 가스 한도를 넘으면 호출이 실패하며, 상태 배열 전체를 반드시 순회하는 구조에서는 기능이 실행 불가능해지는 DoS 문제가 생길 수 있다.

`previewDoubled`의 memory 배열은 함수 실행 동안 존재하는 임시 데이터이므로 변경해도 storage 상태 변수 `scores`에는 영향이 없다.

`delete scores[msg.sender][0]`은 첫 원소를 0으로 초기화하고 배열 길이는 유지한다. `scores[msg.sender].pop()`은 마지막 원소를 제거하고 길이를 1 감소시킨다.
