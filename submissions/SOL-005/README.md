# SOL-005 채점 기록

## 결과

통과

## 충족한 요구사항

- 주소별 등록 상태와 골드를 mapping으로 저장
- 중첩 mapping으로 방향성 있는 결투 동의 저장
- `msg.sender`를 사용해 호출자 본인의 상태만 변경
- 양방향 동의를 `&&`로 확인
- `delete`로 호출자의 등록 상태와 골드를 기본값으로 초기화

## 피드백 반영 과정

처음에는 `setDuelPermission`을 `view`로 선언하고 mapping을 변경하지 않은 채 지역 변수 `allowed`에 조회 결과를 대입했다. 설정 함수에서는 `view`를 제거하고 다음처럼 상태에 직접 대입하도록 수정했다.

```solidity
duelPermission[msg.sender][opponent] = allowed;
```

채팅의 Markdown 코드 블록과 특수 공백은 복사 흔적으로 보고 채점에서 제외했다. `register`의 대입 표현식 두 개를 튜플로 바로 반환한 구현은 유효하지만, 저장본은 상태 변경과 반환을 구분해 감사하기 쉽게 정규화했다.

## 보안 답변

`addGold`는 다른 주소의 골드를 바꾸지는 못하지만 호출자가 `amount`를 마음대로 정하고 횟수 제한 없이 호출할 수 있어 자기 골드를 무제한 위조할 수 있다.

`removeMyProfile`은 `gold`와 `registered`만 삭제한다. `duelPermission`의 내부 키들은 변경되지 않으며 mapping에는 키 목록이나 길이가 없어 모든 상대 주소를 자동으로 순회해 삭제할 수도 없다. 과거 블록 기록이 남는 것과 별개로, 현재 상태의 결투 허용값 자체가 삭제되지 않았기 때문에 재등록 후에도 남는다.
