# SOL-006 채점 기록

## 충족한 요구사항

- `require`로 중복 등록 방지
- 등록 여부와 훈련량 범위 검사
- 훈련량 1 이상 50 이하의 경계값 처리
- 잔액 부족 시 인자를 포함한 `InsufficientGold` 사용자 정의 오류 발생
- Checks 이후 골드 차감과 누적 소비량 갱신
- `assert`로 `gold + spent == 100` 회계 불변식 검사
- 갱신된 골드 반환

## 피드백 반영 과정

첫 제출에서는 훈련량 조건이 `amount < 50`이어서 0을 허용하고 50을 거부했다. 또한 사용자 정의 오류의 `revert` 문법과 반환값이 누락되었다.

두 번째 제출에서 사용자 정의 오류 문법과 반환값을 수정하고 0을 막았지만 여전히 50을 거부했다. 최종 제출에서는 `amount <= 50 && amount > 0`으로 1부터 50까지 허용해 경계값 요구사항을 충족했다.

채팅의 Markdown 코드 울타리는 복사 흔적으로 보고 저장본에서 제거했다.

## 보안 답변

중복 등록 검사가 없다면 플레이어가 골드를 소비한 뒤 `register()`를 다시 호출해 잔액을 100으로 초기화할 수 있다. 이를 반복하면 의도한 총 소비 한도를 우회한다.

잔액 부족으로 `revert`하면 현재 호출 전체가 되돌아가므로 `gold`와 `spent`는 호출 전 값을 유지한다.

등록 여부는 사용자가 충족하거나 위반할 수 있는 실행 전제조건이므로 `require`로 검사한다. `gold + spent == 100`은 컨트랙트 로직이 항상 보존해야 하는 내부 회계 불변식이므로 `assert`로 검사한다.
