# SOL-007 채점 기록

## 결과

통과

## 충족한 요구사항

- 중복 등록을 막고 등록 후 `PlayerRegistered` 발생
- 승자와 패자의 등록 여부 검사
- 자기 자신을 패자로 지정하는 호출 차단
- 승수 증가 후 갱신된 값으로 `MatchRecorded` 발생
- `winner`와 `loser`를 `indexed`로 선언
- 갱신된 승수 반환

## 피드백 반영 과정

첫 제출은 이벤트 선언, 승수 변경, 이벤트 발생 순서와 반환값을 올바르게 구현했다. 다만 패자의 등록 여부 검사가 빠져 임의 주소를 패자로 기록할 수 있었다.

최종 제출에서 `require(registered[loser], "Loser not registered")`를 추가해 승자와 패자가 모두 등록된 경우에만 기록하도록 수정했다. 채팅에 포함된 특수 공백은 복사 흔적으로 보고 저장본에서 일반 공백으로 정규화했다.

## 보안 답변

현재 함수는 실제 경기 결과를 검증하거나 기록 권한을 제한하지 않는다. 따라서 등록된 사용자는 등록된 다른 주소를 패자로 지정해 `recordWin`을 반복 호출하고 자신의 승수를 임의로 증가시킬 수 있다.

호출이 나중에 실패하면 그 호출에서 먼저 발생시킨 이벤트도 상태 변경과 함께 되돌아가므로 최종 트랜잭션 로그에 남지 않는다.

`winner`와 `loser`가 인덱싱되어 있어 특정 주소가 승자 또는 패자로 등장한 경기 로그를 효율적으로 필터링할 수 있다. `winnerTotalWins`는 로그 데이터에서 읽을 수 있지만 승수 값으로 토픽 필터링할 수는 없다. 현재 총승수는 `wins(player)`로 조회할 수도 있다.
