# 종합과제 SOL-019: Audit Arena 미니 결투

## 목적

지금까지 배운 Solidity 문법과 ERC-20/ERC-721, 상태 머신, 접근 제어, 외부 호출, CEI, 재진입 방어를 하나의 실행 가능한 게임으로 통합한다.

이 과제는 최종 Audit Arena의 축소판이다. **실제 컨트랙트 구현은 학습자가 직접 작성한다.** 튜터 예제 `lessons/18-erc20-erc721-arena/MiniArena.sol`를 그대로 복사해 제출하지 않는다. 막히면 요구사항을 작은 함수 단위로 나누어 질문할 수 있다.

## 게임 규칙

- 두 플레이어가 각자 ERC-721 영웅 1개와 고정 ERC-20 참가비를 맡기면 경기가 시작된다.
- 두 영웅은 각각 HP 100으로 시작한다.
- 자기 턴에 공격하면 상대 HP가 25 감소한다. 이번 과제에는 랜덤 피해나 방어 행동이 없다.
- HP가 0이 된 순간 경기는 종료되고, 상대가 승자가 된다.
- 승자는 두 참가비 합계(2배)를 상금 크레딧으로 받는다. 상금 전송은 공격 함수 안에서 하지 않고 승자가 별도로 출금한다.
- 열린 경기의 생성자는 상대 참가자가 들어오기 전까지 취소할 수 있다. 취소 시 참가비는 환불 크레딧으로, 영웅은 돌려받을 수 있는 상태로 기록한다.
- 종료된 경기의 영웅도 각 소유자가 별도로 찾아간다. 한 사람의 NFT 수신 실패가 상대의 게임 종료를 막아서는 안 된다.

상수는 예를 들어 `ENTRY_FEE = 10 ether`(토큰 최소 단위)와 `DAMAGE = 25`로 둘 수 있다. ERC-20의 decimals에 따라 표기 단위가 달라질 수 있으므로 설명을 덧붙인다.

## 구현 범위

별도 폴더 `exercises/SOL-019-audit-arena-mini/`에서 구현한다. ERC 토큰을 직접 새로 만들 필요는 없다. 18강의 OpenZeppelin 기반 데모 토큰/NFT와 Foundry 실행 절차를 참고해 실제 로컬 테스트가 가능하게 한다.

### 1. 토큰 연결과 에스크로

- 생성자에서 실제 배포된 ERC-20과 ERC-721 주소를 받는다. 주소가 0이 아닌지 확인한다.
- OpenZeppelin 인터페이스/라이브러리를 설치해 import하고, ABI 선언만으로 토큰 구현이 생긴다고 가정하지 않는다.
- 참가자는 ERC-20 allowance와 ERC-721 승인을 각각 아레나에 부여해야 한다.
- ERC-20 참가비를 정확히 받았는지 확인한다.
- NFT를 아레나가 안전하게 수령하도록 `IERC721Receiver`를 구현한다. 설정된 NFT 컨트랙트의, 현재 입장 흐름에서 기대한 토큰만 받아야 한다.
- 에스크로 중 실제 NFT 소유자는 아레나이며, 경기 기록은 원래 플레이어와 토큰 ID를 보존한다.
- 플레이어는 동시에 하나의 열린/진행 중 경기만 가질 수 있고, 같은 NFT를 두 경기에 등록할 수 없다.

### 2. 경기 상태 머신

`enum`과 `struct`를 사용해 최소한 다음 상태와 정보를 관리한다.

- 상태: 열린 참가 대기, 진행 중, 승리로 종료, 생성자 취소
- 두 플레이어 주소와 각자의 영웅 토큰 ID
- 각 플레이어 HP, 현재 턴, 승자
- 경기별 상태와 플레이어별 현재 경기 조회

필수 외부 동작은 다음과 같다. 함수 이름과 인자 형식은 직접 설계하고 README에 기록한다.

1. 경기 생성: 첫 플레이어가 참가비와 영웅을 예치하고 상대를 기다린다.
2. 참가: 다른 주소가 자기 참가비와 영웅을 예치하면 경기가 시작된다.
3. 공격: 진행 중이며 호출자가 현재 턴인 경우에만 상대 HP를 감소시킨다.
4. 취소: 상대 참가 전 생성자만 요청할 수 있다.
5. 상금/환불 출금: 기록된 크레딧을 소유자가 직접 출금한다.
6. 영웅 수령: 경기의 원래 소유자만 지정한 수령 주소로 NFT를 가져간다.

열린 경기에서 생성자가 자기 경기로 다시 참가할 수 없게 하고, 한 경기 안에서 두 플레이어가 서로 다른 주소여야 한다.

### 3. 회계와 외부 호출

- 참가비는 경기에 귀속된 총액으로 관리한다.
- 경기 종료 시 상금을 승자의 출금 가능 크레딧에 한 번만 반영한다.
- 취소 시 생성자에게 환불 크레딧을 한 번만 반영한다.
- 출금 시 크레딧을 먼저 0으로 만들고 토큰 전송을 수행한다. 전송 실패는 기록과 함께 되돌아가야 한다.
- 공격 함수는 승리 결과와 크레딧만 기록하고 토큰/NFT 외부 전송은 하지 않는다.
- 상태 변경과 토큰/NFT 전송이 함께 필요한 함수는 검증 → 상태 갱신 → 외부 호출 순서를 검토하고, 재진입 방어를 적용한다.
- 불필요한 관리자 출금 권한이나 임의의 타인 자산 이동 기능을 만들지 않는다.

### 4. 이벤트와 오류

경기 생성, 참가, 공격, 종료, 취소, 상금/환불 출금, 영웅 수령을 외부에서 추적할 수 있도록 이벤트를 설계한다. 행위자, 경기 ID, 결과와 관련 금액 등 검색에 필요한 값을 포함한다.

실패 조건은 명확한 오류 또는 사용자 정의 오류로 처리한다. 적어도 잘못된 경기 상태, 턴이 아닌 호출자, 본인 경기 재참가, 승인/토큰 전송 실패, 중복 출금/수령을 구분한다.

## 반드시 지켜야 할 불변식

1. 경기의 두 참가자는 서로 다른 주소다.
2. 진행 중 경기의 현재 턴은 두 참가자 중 한 명이다.
3. 경기 종료 후에는 공격할 수 없고 승자는 한 번만 정해진다.
4. 경기 참가비 총액은 열린 경기의 예치액, 종료 경기의 승자 크레딧, 취소 경기의 환불 크레딧으로 정확히 설명된다.
5. 같은 참가비가 두 번 이상 출금되지 않는다.
6. 각 예치 NFT는 원래 경기 참가자만 수령할 수 있고, 한 번만 수령된다.
7. 한 참가자의 토큰/NFT 전송 실패가 다른 경기나 다른 참가자의 출금을 막지 않는다.
8. 실패한 참가/공격/출금은 부분 상태만 남기지 않는다.

먼저 과제 폴더를 만들고 18강의 데모 토큰/NFT를 배포한다. 이어서 Alice와 Bob에게 테스트 토큰과 영웅 NFT를 발행하고, 두 승인을 준 뒤 Alice 생성 → Bob 참가 → 번갈아 공격 → 승자 출금/양쪽 NFT 수령 흐름을 확인한다. 취소 경로도 별도 테스트한다.

## 최소 테스트 체크리스트

- 승인 없는 ERC-20 또는 ERC-721 입장 시 실패하고 잔액·소유권·상태가 변하지 않는다.
- 생성자 경기 생성 후 상태가 참가 대기이며 NFT는 아레나가 보유한다.
- 제3자 참가로 두 플레이어 경기가 시작된다.
- 자기 차례가 아닌 공격, 자기 경기 재참가, 종료 후 공격이 실패한다.
- 공격할 때마다 턴이 교대하며, 4번째 유효 공격에서 HP 0과 승자가 정확히 기록된다.
- 승자 상금은 정확히 참가비 2배이고 한 번만 출금된다.
- 미참가 경기 취소는 생성자에게 정확히 참가비를 환불한다. 타인의 취소와 참가 후 취소는 실패한다.
- 참가자만 자기 NFT를 수령할 수 있고 중복 수령은 실패한다.
- NFT 수령을 거부하는 컨트랙트 주소를 써도 상대 플레이어는 자기 NFT를 수령할 수 있다.
- 악의적인 토큰/NFT 수신자 콜백으로 재진입을 시도해도 상금 중복 지급, 이중 수령, 경기 상태 훼손이 발생하지 않는다.
