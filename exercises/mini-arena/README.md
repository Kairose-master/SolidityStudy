# 과제: MiniArena 영웅 입장 시스템

## 진행 상태

과제 요구사항과 튜터 예시 코드를 제공했다. 예시 코드는 `../../lessons/18-erc20-erc721-arena/MiniArena.sol`에 있다. 학습자의 독립 구현이나 실행 결과는 아직 받지 않았으므로 통과 처리하지 않는다.

## 목표

ERC-20 입장료를 받고 ERC-721 영웅을 에스크로에 맡긴 뒤, 플레이어가 나갈 때 영웅을 돌려주는 최소 아레나를 구현한다. 입장료는 환불하지 않고 지정된 보물고 주소로 보낸다. 전투와 보상은 이번 과제 범위에 포함하지 않는다.

## 실행 전제

이번 과제는 ERC-20/ERC-721 토큰 자체를 새로 구현하는 과제가 아니다. 두 표준 토큰 컨트랙트를 별도로 준비해 배포하고, 그 주소를 MiniArena 생성자에 넣는다. Remix에서 OpenZeppelin 기반 토큰을 쓰거나 표준을 따르는 테스트용 mock을 사용할 수 있다. 플레이어는 입장 전에 ERC-20 사용 한도와 NFT 이동 권한을 각각 아레나에 승인한다.

예제의 로컬 인터페이스는 컴파일러에 함수 시그니처를 알려주는 ABI 선언이다. 실제 토큰 구현이나 주소를 대신 만들어 주지 않는다.

## 요구사항

- 생성자에서 ERC-20 토큰, ERC-721 토큰, 보물고 주소와 입장료를 설정한다.
- 플레이어당 동시에 영웅 하나만 맡길 수 있다.
- `enterArena(tokenId)`는 플레이어가 NFT의 현재 소유자인지 확인한다.
- 입장 시 ERC-20 `transferFrom`으로 입장료를 보물고에 보내고, ERC-721 `safeTransferFrom`으로 영웅을 아레나에 맡긴다.
- `mapping`으로 플레이어별 영웅과 영웅별 예치자를 기록하고, 입장 여부도 확인할 수 있게 한다.
- `leaveArena()`는 입장한 플레이어만 호출할 수 있으며 기록을 정리한 뒤 NFT를 돌려준다.
- 입장·퇴장 이벤트를 발생시킨다.
- `safeTransferFrom` 수신을 위해 `IERC721Receiver` 콜백을 구현한다.

## 확인 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| ERC-20 입장료 승인이 없을 때 입장 | 실패하고 상태 변경도 남지 않음 |
| NFT 승인이 없거나 다른 사람의 NFT로 입장 | 실패하고 상태 변경도 남지 않음 |
| 같은 플레이어가 두 번째 영웅으로 입장 | 실패 |
| 입장 성공 | 수수료는 보물고로 이동, NFT 실제 소유자는 아레나, mapping은 예치자를 기록 |
| 다른 주소가 퇴장 호출 | 실패 |
| 예치 플레이어가 퇴장 | NFT가 플레이어에게 돌아가고 mapping 기록이 정리됨 |
