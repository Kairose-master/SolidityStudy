# 1강 — 컨트랙트 선언과 `pragma`

## 학습 기록

- 문제 번호: `SOL-001`
- 문제명: 두 번의 인사
- 난이도: Bronze 5
- 채점 결과: **통과**

## 학습 목표

- SPDX 라이선스 식별자의 의미
- `pragma solidity`를 통한 컴파일러 버전 범위 지정
- `contract` 선언 방법
- 상태 변수의 기본 형태
- `public` 상태 변수에 자동 생성되는 getter
- 하나의 Solidity 파일에 여러 컨트랙트를 선언하는 방법

## 핵심 내용

### SPDX 라이선스 식별자

```solidity
// SPDX-License-Identifier: MIT
```

소스 코드의 라이선스를 기계가 읽을 수 있는 형태로 표시한다. 일반적으로 각 Solidity 소스 파일의 첫 줄에 작성한다.

### 컴파일러 버전 선언

```solidity
pragma solidity ^0.8.24;
```

`^0.8.24`는 `>=0.8.24 <0.9.0`을 의미한다. `pragma` 자체가 컴파일러를 설치하거나 변경하지는 않으며, 현재 컴파일러가 선언된 범위와 일치하는지 검사한다.

### 컨트랙트와 자동 getter

```solidity
contract Hello {
    string public message = "Hello, world!";
}
```

컨트랙트는 상태 변수와 함수를 담는 스마트 컨트랙트의 기본 단위다. 하나의 `.sol` 파일에 여러 컨트랙트를 선언할 수 있다.

상태 변수를 `public`으로 선언하면 Solidity 컴파일러가 값을 조회하는 getter를 자동으로 생성한다. `public`은 누구나 값을 읽을 수 있다는 뜻이며, 누구나 값을 변경할 수 있다는 뜻은 아니다.

## 연습문제 SOL-001 — 두 번의 인사

하나의 `TwoGreetings.sol` 파일에 다음 조건을 만족하는 코드를 작성한다.

1. 라이선스를 `MIT`로 표시한다.
2. Solidity `0.8.24` 이상, `0.9.0` 미만을 허용한다.
3. `Morning`과 `Evening`이라는 두 컨트랙트를 선언한다.
4. `Morning`에는 `"Good morning!"`을 저장하는 `public message`가 있어야 한다.
5. `Evening`에는 `"Good evening!"`을 저장하는 `public message`가 있어야 한다.
6. 직접 작성한 함수, 생성자, 상속 및 `import`는 사용하지 않는다.
